# Application web progressive (PWA)

`Adex.Mvc` est installable comme application sur téléphone et ordinateur. L'installation ne change aucune fonctionnalité métier et n'ajoute ni notifications push, ni authentification, ni backend, ni dépendance.

## Éléments en place (`Adex.Mvc/wwwroot`)

| Fichier | Rôle |
|---|---|
| `manifest.webmanifest` | Nom, nom court `ADEX`, `start_url` `/?source=pwa`, `scope` `/`, `display: standalone`, `theme_color` `#202b36`, `background_color` `#ffffff`, icônes. |
| `icons/icon-192.png`, `icons/icon-512.png` | Icônes « any » (logo du `favicon.svg`). |
| `icons/icon-maskable-512.png` | Icône « maskable » (logo réduit pour rester dans la zone de sécurité). |
| `icons/apple-touch-icon.png` | Icône d'écran d'accueil iOS (180×180). |
| `sw.js` | Service worker (portée `/`). |
| `offline.html` | Page affichée quand le réseau est indisponible. |
| `js/pwa.js` | Enregistrement du service worker, bouton d'installation, aide iOS. |

`_Layout.cshtml` déclare le manifeste, `theme-color`, l'icône Apple et les métadonnées `apple-mobile-web-app-*` / `mobile-web-app-capable`, charge `pwa.js` et ajoute l'entrée « Installer l'application » au menu. La page **Paramètres** contient une section « Application » (bouton, aide iOS, rappel Chrome/Edge). Le CSS gère les zones de sécurité (`env(safe-area-inset-*)`) en mode autonome.

## Stratégie de cache

ADEX affiche des données en direct (API, base PostgreSQL) : **l'application ne fonctionne pas hors ligne** et ne le promet pas.

- Seuls `offline.html` et deux icônes sont pré-mis en cache (`adex-shell-v1`).
- Les navigations sont en « réseau d'abord » sans mise en cache ; en cas d'échec réseau, la page hors ligne explicite est affichée.
- Les autres requêtes (API, JSON, CSV, scripts, styles, `/mcp`) ne sont pas interceptées ni mises en cache.
- Pour invalider le cache, incrémenter `CACHE_NAME` dans `sw.js`.

## Conditions requises

- **HTTPS en production** (ou `localhost` en développement) : sans contexte sécurisé, ni service worker ni installation. En production, le certificat est terminé par Cloudflare (voir [Déploiement](008_deployment_onpremise.md)) ; `UseForwardedHeaders` restaure le schéma HTTPS.
- Le manifeste, `sw.js` et les icônes doivent être servis sans authentification ni redirection (c'est le cas : fichiers statiques).
- Ne pas mettre `sw.js` en cache longue durée côté CDN/Cloudflare.

## Installation par plateforme

| Plateforme | Procédure |
|---|---|
| Android (Chrome, Edge, Samsung Internet) | Bouton « Installer l'application » (menu ou Paramètres) ou menu du navigateur → « Installer l'application ». |
| Windows / macOS / Linux (Chrome, Edge) | Bouton « Installer l'application », icône d'installation dans la barre d'adresse ou menu → « Installer ADEX ». |
| iPhone / iPad | Pas d'invite standard : Partager → « Sur l'écran d'accueil » → « Ajouter » (Safari ; selon la version, Chrome/Edge/Firefox iOS le proposent aussi). Une aide s'affiche sur iOS. |
| macOS Safari 17+ | Fichier → « Ajouter au Dock ». |

## Limites de compatibilité

- Le bouton n'apparaît que si le navigateur émet `beforeinstallprompt` (Chromium : Chrome, Edge, Samsung Internet, Opera). Il est masqué si l'application est déjà installée ou ouverte en mode autonome.
- Firefox (ordinateur) et Safari n'émettent pas cet événement : pas de bouton, procédure manuelle seulement (Firefox ordinateur ne sait pas installer de PWA ; Firefox Android propose « Installer »).
- iOS : l'installation dépend de la version et du navigateur ; le service worker et les icônes sont gérés par WebKit avec des limites propres.
- Ces comportements n'ont pas été testés sur appareils réels dans ce dépôt ; seule la présence des fichiers et des liens a été vérifiée.
